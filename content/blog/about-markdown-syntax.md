# Markdown 核心语法指南

## Markdown 是一种轻量级标记语言，用于使用纯文本编写文档  
它的核心目标是“易读易写”：即使在发布成 HTML 之前，原始文本也应保持高可读性。无论你是写博客、技术文档，还是简单的笔记，掌握 Markdown 都能让你的写作更高效、排版更优雅。

---

## 1. 基础语法

本节内容由浅入深，详细介绍最常用的 Markdown 标记，用于日常写作和文档编辑。

### 1.1 标题（Headings）

* 使用 `#` 创建标题，`#` 的数量代表标题层级（1–6 级）。
* 建议在 `#` 与标题文本之间保留一个空格，提升可读性。
* 示例：

  ```md
  # 一级标题
  ## 二级标题
  ### 三级标题
  #### 四级标题
  ##### 五级标题
  ###### 六级标题
  ```
* **最佳实践**：保持标题层级连续，不要跳跃（例如不要直接从 `#` 跳到 `###`）。

### 1.2 段落与换行

* 段落：连续的文本行即构成一个段落。
* 换行：在行尾添加两个或以上空格后回车，或使用 HTML `<br/>` 标签。
* 示例：

  ```md
  这是第一段。
  这是第二段，中间空一行分隔。  

  这是紧接上一行的换行。<br/>
  你看到了换行效果。
  ```

### 1.3 强调（Emphasis）

* **粗体**：`**文本**` 或 `__文本__`
* *斜体*：`*文本*` 或 `_文本_`
* ***粗斜体***：`***文本***` 或 `___文本___`
* 注意：在文本或标点与符号之间留空格，避免解析器误判。
* 示例：

  ```md
  **这是粗体**  
  *这是斜体*  
  ***这是粗斜体***  
  ```

### 1.4 引用（Blockquotes）

* 使用 `>` 开头表示引用文本。
* 支持多层嵌套，每多一层添加一个 `>`。
* 示例：

  ```md
  > 这是第一层引用。
  >
  > > 这是第二层引用。
  > > 
  > > > 第三层引用。
  ```
* Tip：引用段落之间加空行，确保渲染器正确分隔。

### 1.5 列表（Lists）

#### 1.5.1 无序列表

* 使用 `*`、`-` 或 `+`。
* 例：

  ```md
  - 项目 A
  - 项目 B
    * 子项目 B1
    * 子项目 B2
  + 项目 C
  ```

#### 1.5.2 有序列表

* 数字加 `.` 自动编号。
* 例：

  ```md
  1. 第一项
  2. 第二项
     1. 子项 2.1
     2. 子项 2.2
  3. 第三项
  ```

#### 1.5.3 列表中的段落与代码

* 若列表项包含多段文字或代码块，需在后续行前缩进 4 个空格或一个制表符。
* 例：

  ```md
  * 列表项的第一段。

      这是同一列表项内的第二段，需要缩进。

  * 另一个列表项。
  ```

### 1.6 代码（Code）

#### 1.6.1 行内代码

* 使用单个反引号 `` ` `` 包裹。
* 示例：

  ```md
  在命令行输入 `npm install`。
  ```

#### 1.6.2 代码块

* 三个反引号 ``` 开始和结束，可指定语言高亮。
* 示例：

  ````javascript
  ```javascript
  function hello(name) {
    console.log(`Hello, ${name}!`);
  }
  ````

  ```
  ```
* **Tip**：始终指定语言，方便阅读与调试。

### 1.7 分隔线（Horizontal Rules）

* 使用三个或以上的 `***`、`---` 或 `___`。
* 示例：

  ```md
  ***

  ---

  ___
  ```

### 1.8 链接与图片（Links & Images）

#### 链接

* **行内链接**：`[文本](URL "可选标题")`

  ```md
  [OpenAI](https://openai.com "OpenAI 官网")
  ```
* **参考式链接**：正文简洁，链接在文末统一管理

  ```md
  访问 [示例网站][1] 获取更多信息。

  [1]: https://example.com "示例链接"
  ```

#### 图片

* 语法与链接类似，前缀 `!`
* 示例：

  ```md
  ![示例图片](/path/to/image.png "可选标题")
  ```

> **无障碍提示**：`Alt Text` 应具描述性，帮助视觉障碍用户。

## 2. 扩展语法与平台特性

在 GitHub、GitLab、Notion、Obsidian 等现代编辑器或平台，可使用以下扩展语法。

### 2.1 表格（Tables）

* 使用 `|` 分隔列，表头和表体之间用 `-`。
* 可通过 `:` 控制对齐方式。
* 示例：

  ```md
  | 左对齐 | 居中对齐 | 右对齐 |
  | :----- | :------: | -----: |
  | A      |   B      |      C |
  | D      |   E      |      F |
  ```

### 2.2 删除线（Strikethrough）

* 使用 `~~文本~~`
* 示例：

  ```md
  ~~已删除内容~~ 
  ```

### 2.3 任务列表（Task Lists）

* 使用 `- [ ]`（未完成）或 `- [x]`（已完成）
* 示例：

  ```md
  - [x] 完成第一步
  - [ ] 进行第二步
  ```

### 2.4 脚注（Footnotes）

* 使用 `[^标识]` 和文末定义。
* 示例：

  ```md
  这是一个脚注示例[^1]。

  [^1]: 这是脚注内容。
  ```

### 2.5 自动链接（Auto Links）

* 包裹在尖括号中即可自动识别为链接。
* 示例：

  ```md
  <https://example.com>
  ```

### 2.6 注解与高亮（Comments & Highlights）

* HTML 注释：`<!-- 注释内容 -->`
* GFM 标记高亮（部分平台支持）：`==高亮文本==`

## 3. 常见误区与优化技巧

1. **空格与缩进不当**

   * 列表、引用、代码块对缩进敏感，建议开启编辑器显示不可见字符。
2. **标题层级跳跃**

   * 保持层级顺序，避免 SEO 影响和阅读混乱。
3. **滥用表格**

   * 表格适用于结构化数据，过多会降低可读性。
4. **链接管理混乱**

   * 长文档推荐统一使用参考式链接，方便维护。
5. **不指定语言**

   * 代码块不指定语言会丧失高亮，影响阅读与排版。

## 4. 实战示例

下面示例展示了如何在技术博客中结合代码与链接：

````md
### 使用 `content:file:afterParse` 钩子计算阅读时长

更多细节请参考 Nuxt Content 官方文档：  
[Hooks 文档](https://content.nuxt.com/docs/advanced/hooks#contentfileafterparse)

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  hooks: {
    'content:file:afterParse'(ctx) {
      const { file, content } = ctx
      if (file.extension === '.md') {
        const wordsPerMinute = 180
        const text = typeof file.body === 'string' ? file.body : ''
        const wordCount = text.split(/\s+/).length
        content.readingTime = Math.ceil(wordCount / wordsPerMinute)
      }
    }
  }
})
```
